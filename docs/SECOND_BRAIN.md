# 세컨브레인 운영 구조

이 저장소의 세컨브레인은 “무엇을 항상 기억할지”와 “필요할 때 찾아볼 기록”을 분리한다. Notion은 사람이 읽는 업무 일지이며 저장소 정본을 대체하지 않는다.

## 정보 계층

| 계층 | 역할 | 갱신 기준 |
|---|---|---|
| `AGENTS.md` | Codex가 매번 따라야 할 짧은 운영 규칙 | 같은 실수가 반복되거나 공통 작업 방식이 바뀔 때 |
| `PROJECT_RULES.md` | 제품 불변식·안전·검증 기준 | 아키텍처나 팀 정책이 바뀔 때 |
| `PATHS.md` | 현재 경로 지도 | 디렉터리 구조가 바뀔 때 |
| `HANDOFF.md` | 활성 작업을 찾는 짧은 인덱스 | 활성화·상태·다음 행동이 바뀔 때 |
| `handoff/<작업>.md` | 작업별 현재 상태, 결정, 검증, 다음 단계 | 의미 있는 작업 분기점과 세션 종료 시 |
| `docs/processes/` | 특정 작업 유형에서만 읽는 절차·체크리스트 | 해당 프로세스가 바뀔 때 |
| `templates/` | 보고서·PR 등 복사해 쓰는 양식 | 산출물 형식이 바뀔 때 |
| `.codex/` | Codex 설정과 기계적으로 검사할 훅 | Codex 실행 계약이 바뀔 때 |
| `.claude/` | Claude 세션 전용 설정·훅·skill | Claude 세션에서만 관리할 때 |
| `discussion/` | 선택지와 판정 근거가 필요한 설계 기록 | 고위험·고비용 갈림길이 있을 때 |
| `logs/` | 재현 증적, 장문 분석, 완료 이력 | 원문 증거 보존이 필요할 때 |
| Notion 작업일지 | 날짜별 인간 친화 요약과 회고 | 자동 또는 수동 일일 기록 |

## 기록 규칙

- 같은 사실을 여러 계층에 복사하지 않고 정본 링크를 남긴다.
- HANDOFF에는 작업명, 현재 상태, 다음 행동, 상세 파일 링크만 둔다.
- 상세 handoff는 현재 스냅샷을 유지하고 원문 로그·과거 연혁 대신 증적 경로를 링크한다.
- 완료 작업은 `logs/HANDOFF_ARCHIVE.md`로 옮기고 활성 인덱스에서 제거한다.
- 반복되는 보편 규칙은 handoff에서 `PROJECT_RULES.md`나 `AGENTS.md`로 승격하고 기존 위치에는 링크만 남긴다.
- 특정 작업 유형에서만 필요한 절차는 `docs/processes/`, 복사 양식은 `templates/`, 기계적 검사는 스크립트·훅으로 분리한다.
- 날짜가 있는 환경 스냅샷은 다음 세션에 자동으로 사실로 간주하지 않는다. git·프로세스·DB에서 다시 확인한다.

## 규칙 배치 기준

- **항상 적용할 강력한 규칙**: 권한·안전·데이터 손실·사용자 변경 보존처럼 작업 종류와 무관한 내용만 `AGENTS.md` 또는 `PROJECT_RULES.md`에 둔다.
- **프로세스 규칙**: UI/Jira, DB 변경, PR·보고서처럼 특정 작업에서만 필요한 순서와 체크리스트는 `docs/processes/`에 둔다.
- **양식과 예시**: 길이가 늘어나는 복붙 블록과 스타일은 `templates/`로 이동한다.
- **현재 상태와 역사**: 현재 판단에 필요한 최소 상태만 handoff에 두고, 과거 경위와 긴 증적은 `logs/` 또는 `discussion/`에 둔다.
- 사고가 발생해도 같은 교훈을 여러 문서에 복제하지 않고 위 기준에 맞는 정본 한 곳만 고친다.

상시 규칙이 8KB, 조건부 프로세스가 16KB, 작업 handoff가 20KB를 넘거나 규칙·양식·역사가 한 파일에 섞이면 사전 확인 없이 자동 정리한다.

- 원문 전체를 `logs/`에 보존하거나 git 이력으로 복구 가능함을 먼저 확인한다.
- 현재 판단에 필요한 상태·결정·다음 행동만 원래 경로에 남긴다.
- 과거 경위는 `logs/`, 복붙 양식은 `templates/`, 조건부 절차는 `docs/processes/`로 옮기고 상호 링크한다.
- 요구사항의 의미가 달라지거나 기록 손실 가능성이 있으면 자동 축약하지 않고 원문 보존본과 현재 요약을 병행한다.
- 완료 후 이동 경로, 전후 크기, 링크·인코딩 검증 결과를 사용자에게 보고한다.

## 작업 상세 최소 형식

새 작업은 `handoff/TEMPLATE.md`를 복사해 만든다.

- 현재 상태: 지금 사실인 것
- 목표·완료 조건: 끝났다고 판단할 기준
- 결정: 선택과 이유
- 검증: 명령·결과·증적
- 다음 행동: 바로 실행 가능한 순서
- 블로커·위험: 사용자 결정이나 외부 상태가 필요한 것

## 검색 순서

1. 사용자 요청의 명사·이슈 번호로 `HANDOFF.md`를 검색한다.
2. 연결된 작업 상세에서 최신 상태와 다음 행동만 읽는다.
3. 코드·git·실행 상태로 오래된 기록을 검증한다.
4. 과거 경위가 필요할 때만 `discussion/`과 `logs/`를 연다.

## 일일 작업일지

`scripts/daily_worklog.py`는 git과 Codex 세션을 기본 원자료로 삼고, 사용자가 Claude를 명시적으로 사용한 날에는 Claude 세션 기록도 읽기 전용으로 함께 수집한다. 이 수집은 Claude 프로세스를 실행하지 않는다. Codex와 Claude 세션은 `AGENTS.md`, `PROJECT_RULES.md`, `PATHS.md`, `HANDOFF.md`, `handoff/`, `logs/`를 공통 작업 이력으로 사용한다. HANDOFF는 작업 연결성을 보조하는 입력일 뿐이며, 오래된 HANDOFF 문장을 현재 사실로 확정해서는 안 된다. 비밀값·전체 로그·불필요한 대화 원문은 Notion으로 보내지 않는다.
