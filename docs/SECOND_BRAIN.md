# 세컨브레인 운영 구조

이 저장소의 세컨브레인은 “무엇을 항상 기억할지”와 “필요할 때 찾아볼 기록”을 분리한다. Notion은 사람이 읽는 업무 일지이며 저장소 정본을 대체하지 않는다.

## 정보 계층

| 계층 | 역할 | 갱신 기준 |
|---|---|---|
| `AGENTS.md` | Codex가 매번 따라야 할 짧은 운영 규칙 | 같은 실수가 반복되거나 공통 작업 방식이 바뀔 때 |
| `PROJECT_RULES.md` | 제품 불변식·안전·검증 기준 | 아키텍처나 팀 정책이 바뀔 때 |
| `PATHS.md` | 현재 경로 지도 | 디렉터리 구조가 바뀔 때 |
| `HANDOFF.md` | 활성 작업을 찾는 짧은 인덱스 | 활성화·상태·다음 행동이 바뀔 때 |
| `handoff/<작업>.md` | 작업별 현재 상태, 결정, 검증, 다음 단계 | 의미 있는 작업 분기점과 세션 종료 시 |
| `discussion/` | 선택지와 판정 근거가 필요한 설계 기록 | 고위험·고비용 갈림길이 있을 때 |
| `logs/` | 재현 증적, 장문 분석, 완료 이력 | 원문 증거 보존이 필요할 때 |
| Notion 작업일지 | 날짜별 인간 친화 요약과 회고 | 자동 또는 수동 일일 기록 |

## 기록 규칙

- 같은 사실을 여러 계층에 복사하지 않고 정본 링크를 남긴다.
- HANDOFF에는 작업명, 현재 상태, 다음 행동, 상세 파일 링크만 둔다.
- 상세 handoff는 최신 상태를 위에 두고 원문 로그 대신 증적 경로를 링크한다.
- 완료 작업은 `logs/HANDOFF_ARCHIVE.md`로 옮기고 활성 인덱스에서 제거한다.
- 반복되는 보편 규칙은 handoff에서 `PROJECT_RULES.md`나 `AGENTS.md`로 승격하고 기존 위치에는 링크만 남긴다.
- 날짜가 있는 환경 스냅샷은 다음 세션에 자동으로 사실로 간주하지 않는다. git·프로세스·DB에서 다시 확인한다.

## 작업 상세 최소 형식

새 작업은 `handoff/TEMPLATE.md`를 복사해 만든다.

- 현재 상태: 지금 사실인 것
- 목표·완료 조건: 끝났다고 판단할 기준
- 결정: 선택과 이유
- 검증: 명령·결과·증적
- 다음 행동: 바로 실행 가능한 순서
- 블로커·위험: 사용자 결정이나 외부 상태가 필요한 것

## 검색 순서

1. 사용자 요청의 명사·이슈 번호로 `HANDOFF.md`를 검색한다.
2. 연결된 작업 상세에서 최신 상태와 다음 행동만 읽는다.
3. 코드·git·실행 상태로 오래된 기록을 검증한다.
4. 과거 경위가 필요할 때만 `discussion/`과 `logs/`를 연다.

## 일일 작업일지

`scripts/daily_worklog.py`는 git과 Codex 세션을 원자료로 삼아 Notion용 요약을 만든다. HANDOFF는 작업 연결성을 보조하는 입력일 뿐이며, 오래된 HANDOFF 문장을 현재 사실로 확정해서는 안 된다. 비밀값·전체 로그·불필요한 대화 원문은 Notion으로 보내지 않는다.
