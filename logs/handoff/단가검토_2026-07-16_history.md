## [2026-07-13] 견적 단가검토 — 배송비·기타추가·적용금액계 테이블 구성안 분석 (아티팩트, 코드/DB 변경 없음)

- `B`=배송비·신규 기타추가를 제외한 기존 단가 구성요소 합, `Q`=수량, `D`=배송비, `A`=신규 기타추가.
- 단가합계=`B+D+A`, 금액계=`B×Q+D+A`, 수량 적용가=`B×Q`, 적용 금액계 기본값=`B×Q+D+A`이며 적용 금액계는 사용자 수정 가능.
- 배송비·신규 기타추가는 수량을 곱하지 않고 상세 계산 마지막에 한 번만 더하는 값.
### 저장소 분석 결과
- 기존 `TBL_ESTIMATE_DETAIL.UNIT_ETC_AMT`는 이미 수량이 곱해지는 기존 단가 구성요소이며 견적/수주/엑셀/리포트 등 **29파일 216회 참조**. 신규 기타추가로 재정의하면 과거 데이터와 광범위한 계산식이 깨지므로 재사용 비권고.
- `DELIVERY_AMT`는 estimate-regist/list·order-manage JS 식별자로만 등장하고 SQL 매퍼 영속화가 없음. 상세 팝업의 임시 `UNIT_DELIVERY_AMT`도 DB 응답/UPDATE에 연결되지 않음.
- `UNIT_FINAL_EST_AMT`는 최종 견적 **단가**이므로 사용자가 수정하는 총액 성격의 적용 금액계를 저장할 수 없음. 전용 nullable 컬럼 필요.
- 견적→수주 흐름은 상세 원가를 `TBL_CONTROL_PART`, 주문별 최종단가를 `TBL_ORDER`/매핑에서 소비하므로 향후 신규 가산액을 무조건 CONTROL_PART에 넣으면 다중 주문 매핑별 가격을 분리하지 못할 수 있음.
