# DB 변경 보고 절차

이 문서는 PR·리뷰·보고서에 DB 스키마 또는 저장 루틴 변경이 포함될 때만 `PR_작성규칙.md`와 함께 적용한다.

## 필수 내용

1. **대상과 환경**
   - DB, 스키마, 테이블 또는 루틴, 적용 환경을 명시한다.
2. **변경 전 → 변경 후**
   - 컬럼·인덱스·제약·루틴 정의를 표로 비교한다.
3. **실행 순서**
   - 백업 → 사전 검증 → 데이터 보정 DML → DDL/루틴 교체 → 사후 검증 순서로 적는다.
4. **실제 SQL**
   - 실행한 `CREATE`, `ALTER`, `DROP`, `RENAME`, `UPDATE`, `CALL` 등을 코드 블록에 보존한다.
   - 비밀번호·접속 정보·실고객 데이터는 제거한다.
5. **루틴 계약**
   - 프로시저·함수·트리거는 파라미터, `DEFINER`, 트랜잭션, 내부 `COMMIT`, 권한의 유지 여부와 실제 변경 구문을 적는다.
   - 전문이 길면 `<details>` 안에 전체 DDL 또는 변경 블록과 원문 보관 경로를 둔다.
6. **검증**
   - 사전·사후 검증 `SELECT`, 영향 행 수, 확인 결과를 적는다.
7. **복구**
   - 복구 SQL과 실행 조건, 복구 과정의 데이터 손실·호환성 위험을 적는다.

## 실행 원문이 없을 때

- 추정 SQL을 실제 실행문처럼 쓰지 않는다.
- `실행 원문 미보존`을 명시한다.
- `SHOW CREATE` 등으로 확인한 최종 상태, 재현 SQL, 그 근거를 각각 구분한다.
- 확인되지 않은 적용 순서나 영향 행 수는 추론이라고 표시한다.

## 제출 전 확인

- [ ] 대상·환경과 변경 전후 정의가 있다.
- [ ] 실행 순서와 실제 SQL 또는 원문 미보존 사실이 있다.
- [ ] 루틴 계약의 유지·변경 여부를 확인했다.
- [ ] 검증 쿼리와 결과가 있다.
- [ ] 복구 SQL과 위험이 있다.
- [ ] 민감정보와 실고객 데이터가 없다.
