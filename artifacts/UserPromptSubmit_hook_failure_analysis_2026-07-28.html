UserPromptSubmit 훅 JSON 출력 오류

규칙 변경 알림을 평문으로 출력하던 훅이 Codex의 JSON 판정 규칙과 충돌해 발생한 비차단 오류를 분석하고, 공식 컨텍스트 주입 형식으로 교정한 과정을 정리한다.

해결 완료 발생·수정일 2026-07-28 수정 커밋 185d9ae 영향 범위: 규칙 신선도 알림

현상

규칙 파일 변경 후 다음 프롬프트 제출 시 훅 JSON 오류 표시

직접 원인

[로 시작하는 평문이 잘못된 JSON 배열 후보로 판정됨

해결

알림을 공식 hookSpecificOutput.additionalContext JSON으로 반환

1. 현상과 영향

AGENTS.md, PROJECT_RULES.md, HANDOFF.md 중 하나가 세션 도중 바뀐 뒤 사용자가 다음 프롬프트를 제출하면 아래 오류가 나타났다.

UserPromptSubmit hook (failed) error: hook returned invalid user prompt submit JSON output
구분 관찰 결과 영향
사용자 요청 훅 실패는 비차단이어서 프롬프트 자체는 계속 처리됨 주 작업은 중단되지 않음
규칙 신선도 알림 파싱 실패로 모델 컨텍스트에 전달되지 않음 변경된 정본을 다시 읽어야 한다는 안전 신호 유실
재시도 출력 전 상태 해시는 이미 최신 값으로 저장됨 같은 파일 변경에 대한 알림이 다음 프롬프트에서 재발행되지 않음
중요한 부수 영향 화면에 오류가 한 번 나타나는 데 그치지 않았다. 훅이 상태를 먼저 갱신한 뒤 잘못된 출력을 반환했기 때문에, 오류가 난 알림은 자동 재시도 기회까지 잃었다.

2. 원인 분석

훅은 감시 파일의 SHA-256 해시를 세션별 상태 파일에 저장하고, 이전 해시와 달라진 파일이 있으면 알림을 stdout으로 출력한다. 마이그레이션 당시 알림 문구는 다음과 같은 평문이었다.

1 프롬프트 제출

Codex가 등록된 UserPromptSubmit 명령 훅을 실행

2 변경 감지

세 정본 파일의 현재 해시와 세션 상태의 이전 해시를 비교

3 상태 갱신

현재 해시를 상태 파일에 먼저 기록

4 평문 출력

[규칙 신선도 알림] ...을 stdout으로 반환

5 JSON 파싱 실패

선두 [ 때문에 JSON 배열 후보가 되었지만 유효한 JSON이 아님

직접 원인

해당 Codex 훅 파서는 stdout이 { 또는 [로 시작하면 JSON 출력 후보로 취급한다. 알림은 사람이 읽는 평문이었지만 첫 문자가 [였기 때문에 JSON 배열로 파싱되었고, 따옴표·쉼표·배열 종료 문법이 없는 문자열이라 실패했다.

근본 원인

Claude Code에서 사용하던 평문 컨텍스트 알림 형식을 Codex 훅으로 옮기면서 Codex의 출력 계약을 적용하지 않은 호환성 결함이었다. 초기 전환 검증은 JSON/TOML 설정 파싱, 일반 Codex 실행, 훅의 최초 실행 무출력 경로에 집중했고, 실제로 규칙 파일이 바뀐 뒤에만 열리는 출력 분기를 실행하지 않았다.

3. 수정 내용

알림 문구 자체와 감시 범위는 유지하되, stdout을 Codex가 명시적으로 이해하는 UserPromptSubmit 전용 JSON 구조로 감쌌다.

수정 전 Invalid contract 
print(
    f"[규칙 신선도 알림] ..."
)
수정 후 Valid Codex JSON 
print(json.dumps({
  "hookSpecificOutput": {
    "hookEventName":
      "UserPromptSubmit",
    "additionalContext":
      notice
  }
}, ensure_ascii=False))
왜 이 방식을 채택했는가 알림 앞의 대괄호만 없애는 평문 우회도 당장 오류를 피할 수는 있지만, 파서의 휴리스틱이 바뀌면 다시 깨질 수 있다. 공식 필드로 이벤트 종류와 컨텍스트 목적을 선언하는 방식이 더 명확하고 회귀 가능성이 낮다.
유지한 것 바꾼 것 의도
감시 대상 3개 정본 파일 stdout의 직렬화 형식 기능 범위를 넓히지 않고 호환성만 교정
세션별 해시 상태 저장 hookSpecificOutput 래퍼 추가 기존 실행 비용과 중복 알림 방지 유지
사용자에게 보이는 한국어 알림 문구 additionalContext로 전달 경로 명시 모델이 변경된 규칙을 다시 읽도록 확실히 주입

4. 회귀 테스트와 검증 결과

이전 검증에서 놓친 상태 전이를 그대로 테스트 시나리오로 고정했다. 테스트는 같은 세션 ID와 상태 저장소를 사용해 아래 세 단계를 순서대로 실행한다.

순서 조건 기대 출력 검증
1 세션 최초 실행 기준 해시만 저장하고 stdout 무출력 PASS
2 AGENTS.md 내용 변경 후 실행 유효 JSON, 이벤트명 일치, 변경 파일명 포함 PASS
3 추가 변경 없이 다시 실행 중복 알림 없이 stdout 무출력 PASS

정적·전체 검증

하네스 전체 60개 테스트, Python 컴파일, git diff --check를 통과했다.

실제 수명주기 검증

수정 커밋 이후 실제 다음 사용자 프롬프트에서 오류 대신 규칙 신선도 알림이 개발자 컨텍스트로 정상 주입됐다.

5. 결론과 남은 주의점

이 오류는 감시 로직이나 Python 실행 실패가 아니라, 훅 stdout 형식과 Codex 파서 계약의 불일치였다. 출력 구조를 공식 JSON 계약으로 바꾸고 실제 변경 상태를 포함한 회귀 테스트를 추가해 해결했다.

남은 범위 확인된 UserPromptSubmit 결함은 해결됐다. 다만 최초 전환 검증이 상태 전이 분기를 놓친 전례가 있어, 다른 Codex 훅과 자동화에도 유사한 출력 계약 누락이 없는지는 별도의 전체 런타임 재감사 대상으로 남아 있다.
