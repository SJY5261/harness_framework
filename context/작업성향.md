# 작업 성향

_최종 사용자 확정: 2026-07-30_

이 문서는 작업 협업에 필요한 선호만 기록한다. 성격 진단이나 업무와 무관한 개인 평가는 만들지 않는다.

## 사용자 확정 선호

- 한국어로 명확하고 직접적인 설명을 선호한다.
- 이론상 최고의 일반 해법보다 현재 환경에서 실제로 발생할 상황과 실익을 기준으로 판단하기를 원한다.
- 현재 방식이 목표를 충분히 충족하면 작은 이론적 이득을 위한 불편·품질 저하·오버스펙 변경을 원하지 않는다.
- Codex 사용량이 충분한 동안 토큰 절약을 이유로 모델 품질이나 추론 수준을 낮추지 않는다.
- 기능 변경은 결과만 받기보다 어떤 코드가 왜 바뀌었고 어떻게 검증됐는지 이해하기를 원한다.
- PR 리뷰는 파일·메서드 수가 아니라 독립적으로 이해하고 검증할 수 있는 업무 기능 단위를 선호한다.
- 주제가 달라지면 사용자가 채팅을 분리해 관리한다. Codex는 토큰 절약만을 이유로 불필요한 세션 분리를 요구하지 않는다.
- 시스템에서 안전하게 확인 가능한 환경 정보는 Codex가 직접 조사하고, 확인할 수 없으면서 현재 결과를 바꾸는 정보만 질문하기를 원한다.
- 현재 업무 PC의 작업 도구 실행 파일과 변경 가능한 확장·브라우저·설정·캐시·전용 임시 데이터는 C:가 아니라 D:를 정본으로 사용하기를 원한다. Windows가 위치를 고정하는 시스템 구성요소와 설치 캐시는 예외다.

## 관찰된 협업 방식

- 경로, Jira 번호, 승인 여부, 원하는 산출물 형태를 구체적으로 제시한다.
- 복잡한 결정은 번호로 나눠 검토하고 확정하는 방식을 자주 사용한다.
- 실제 코드·DB·화면·Git 상태를 근거로 한 설명과 검증을 중시한다.
- 중요한 권한·데이터·공개 범위 결정은 직접 통제하고, 안전하고 되돌릴 수 있는 범위 내 실행은 Codex가 끝까지 처리하기를 기대한다.

관찰은 이후 사용자 지시와 충돌하면 즉시 수정하며, 단일 대화의 표현을 영구 성향으로 확대 해석하지 않는다.

## 현재 확인이 필요하지 않은 정보

- 개인 PC의 상세 사양과 업무 PC와의 차이
- IntelliJ Ultimate·Community·VS Code 중 주 편집기
- 응답 속도와 품질 사이의 세부 허용 범위

위 정보는 실제 작업 선택이 달라질 때만 시스템에서 조사하거나 사용자에게 묻는다.
